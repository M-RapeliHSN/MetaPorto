TECHNICAL DOCUMENTATION & DEV LOGS

Catatan keputusan arsitektur, trade-off rekayasa sistem backend, dan dev logs dari implementasi nyata di lingkungan produksi institusional dan sistem reservasi konkuren.

DEV LOG #01: GROW-A-GARDEN — WEATHER AUTOPILOT & SCHEDULED CARE ENGINE

Problem: Jadwal perawatan tanaman rawan terabaikan atau terjadi overwatering saat hujan deras jika hanya mengandalkan input manual pengguna.
Constraint: Mengintegrasikan data API cuaca eksternal ke dalam aturan bisnis lokal tanpa memicu pemanggilan API berulang (rate-limit / cost overhead) pada setiap request pengguna.
Solusi & Keputusan: Membangun arsitektur modular pada service layer (AutopilotService & WeatherService), di mana scheduled console commands mengeksekusi sinkronisasi cuaca secara terisolasi, mengevaluasi threshold rule-engine kelembaban/hujan, dan mengotomatisasi pembaruan task perawatan tanaman dengan event broadcasting real-time via Laravel Reverb.
Hasil & Bukti: Terbukti mengotomatisasi siklus perawatan tanaman multi-kebun secara adaptif berbasis kondisi cuaca riil di repositori publik GitHub.

DEV LOG #02: KAPI — CONCURRENCY & TRANSACTIONAL SEAT LOCKING

Problem: Risiko race conditions dan double booking saat multiple user memilih kursi gerbong kereta yang sama pada milidetik yang identik.
Constraint: Sistem harus menjamin ketersediaan kursi tanpa mengunci seluruh tabel jadwal rute (table-level lock) yang akan mematikan throughput pemesanan pengguna lain.
Solusi & Keputusan: Mengimplementasikan database transactions (DB::transaction) dengan pessimistic row locking (lockForUpdate()) spesifik pada baris relasi kursi dan transisi status atomik.
Hasil & Bukti: Terverifikasi bebas dari race condition melalui test suite Pest PHP (37 automated tests / 98 assertions lolos) di repositori publik GitHub.

DEV LOG #03: WILMARBOOKS — REAL-TIME STATE & CAMPUS WORKFLOW

Problem: Admin perpustakaan kampus membutuhkan notifikasi instan saat donatur mengajukan buku tanpa membebani server dengan polling HTTP berkala.
Constraint: Server kampus memiliki keterbatasan resource dan harus efisien tanpa lonjakan request berulang atau memory leak.
Solusi & Keputusan: Integrasi event-driven broadcasting real-time menggunakan Laravel Reverb WebSockets, dipadukan Google OAuth via Socialite dan dynamic PDF generation untuk tanda terima donasi terverifikasi.
Hasil & Bukti: Beroperasi stabil di production kampus Politeknik Wilmar Bisnis Indonesia (donasi-buku.wbi.ac.id).

DEV LOG #04: INVENTARIS WBI — NORMALIZATION & AUDIT TRAIL

Problem: Pencatatan aset kampus antar divisi rawan redudansi data, riwayat mutasi tidak terdokumentasi, dan akses tanpa otorisasi bertingkat.
Constraint: Setiap mutasi perpindahan aset harus tercatat permanen dalam audit trail tanpa merusak integritas referensial data relasional.
Solusi & Keputusan: Perancangan skema relasional 3NF (Third Normal Form) di MySQL, Role-Based Access Control (RBAC) via Laravel Gate/Policy, dan audit logging riwayat mutasi.
Hasil & Bukti: Menghilangkan anomali relasional dan menjamin pemisahan hak akses antara Staff Divisi, Admin, dan Super Admin.
